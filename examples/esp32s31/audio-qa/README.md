# S31 audio engineering QA

Source-only experimental harness. No firmware, decoded captures, credentials, radio identifiers or BTstack distribution are included. BTstack is an external dependency subject to its own non-commercial license; these small patches do not change those terms. The existing community transport-only default is not modified by the BSP.

Tested community revision: `f76b1e0d5c0d8e6aedcdcac296a093ea18abbcf9`; BTstack revision: `431d58d5613fd8fae38afe50282b25302de84bf7`. Obtain the corresponding source via the community fetch script and apply its four btstack-s31 patches and configuration before applying `a2dp-qa.patch` and `wav-header.patch` in the BTstack source directory. The experimental A2DP executable uses the Bluedroid SBC decoder, POSIX file I/O and direct decode-to-WAV (no physical sound sink), built using `qa-build.py` in that source directory with `S31_CC` pointing at the RV32 soft-float toolchain. The standalone codec and WAV header harnesses are included separately.

For the lab orchestration, use a dedicated working directory with the community checkout at `community-src` and the prepared BTstack tree at `community-src/cache/sources/btstack`. Place the two orchestration scripts and a synthetic 5 s stereo 44.1 kHz signed 16-bit WAV named `tone-stereo.wav` in the working directory. Generate distinct 440 Hz left and 660 Hz right tones. Set `S31_QA_UART` to the board's UART (default /dev/ttyUSB0) and `S31_QA_BT_ADDRESS` to the authorized test board's address. Start the target script, wait for WLAN_SCAN_READY, then run the host script in the same directory. The target script holds the serial session open to preserve the RAM capture; the host script explicitly connects the FL/FR PipeWire ports, checks active BlueZ media transport and requests one passive WLAN scan using shared local markers. No credentials or WLAN association are required. Pairing uses ordinary BlueZ and the community engineering demo, not a production authenticated pairing policy. Never use this test to connect to unrelated devices.

The capture is collected through UART and checked against the target SHA-256. Results apply to the specific engineering configuration and board, not sustained throughput, IP traffic coexistence, physical playback or production qualification.
