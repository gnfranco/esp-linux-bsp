## Over-the-air A2DP hardware tests

Normal BlueZ discovery, engineering-demo pairing, SDP, A2DP connection, explicit PipeWire FL/FR links and active MediaTransport1 state passed. An automatic host routing attempt negotiated the codec but did not start the media stream; it is not counted as a successful audio test. Keeping the UART session open avoids losing RAM artifacts on serial reopen. The source fixture was 5 seconds of synthetic 440/660 Hz stereo tones; the receiver captured additional transport padding.

Two successful captures each recorded 264 media packets, 2,112 indicated and 2,112 good SBC frames, 0 bad/zero frames, 270,336 stereo PCM frames and a 1,081,388-byte file. In both captures the actual PCM payload was byte-identical. After the initial capture we corrected two independent BTstack WAV header errors: sample count already includes channels and block alignment must be expressed in bytes. Native mono/stereo header and sample regressions passed; the fixed RV32 executable was rebuilt, transferred to RAM with verified SHA-256, and retested.

Corrected capture: 44,100 Hz, stereo signed 16-bit PCM, 270,336 frames, valid RIFF/data sizes and four-byte block alignment. Over a 4.9-second interior signal window, peaks were 440.001 and 659.959 Hz, RMS 8443.08 and 8449.70, respectively, zero clipped samples. Opposite-tone spectral rejection at the measured frequency bins was 112.67/117.15 dB (not a calibrated analog crosstalk measurement).

## Associated WLAN + A2DP PCM — final hardware regression

The same combined-radio image and RAM-only WAV-fixed decoder passed a bounded simultaneous IP/audio regression. WPA2-PSK with CCMP pairwise/group ciphers, DHCP and 15/15 baseline gateway pings passed. While BlueZ MediaTransport1 was active, 15 ICMP echo requests with 1,000-byte payloads at 200 ms intervals were sent via wlan0 to the authorized local gateway; 15/15 replies, zero loss. The request started 0.015 s after the host's active-media marker and completion was observed 1.573 s before host playback ended.

The receiver captured 266 media packets, 2,128 indicated and 2,128 good SBC frames, zero bad/zero frames, and 272,384 stereo PCM frames. The 1,089,580-byte WAV was retrieved with matching SHA-256 and valid RIFF/data sizes, 44.1 kHz, stereo 16-bit PCM. The 4.9-second interior tone window yielded 440.001/659.959 Hz, RMS 8475.11/8481.58, zero clipped samples. Both channels contained the intended signal.

Earlier associated-WLAN runs decoded valid but silent PCM. One recorded host sink volume 0.00. The successful run explicitly verified sink volume 0.40 (unmuted) and stream volume 1.00 before linking the channels. The host harness now includes bounded discovery retries and a nonzero sink-volume gate; it no longer forces the sink volume to zero at teardown. This is a host test correction, not a new driver or firmware change. A subsequent physical playback or sustained throughput characterization is outside this test. The fixture is synthetic; the private WLAN configuration and logs are excluded. Temporary receiver/configuration cleanup was confirmed.
