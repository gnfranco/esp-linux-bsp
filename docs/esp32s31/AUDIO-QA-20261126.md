## Over-the-air A2DP hardware tests

Normal BlueZ discovery, engineering-demo pairing, SDP, A2DP connection, explicit PipeWire FL/FR links and active MediaTransport1 state passed. An automatic host routing attempt negotiated the codec but did not start the media stream; it is not counted as a successful audio test. Keeping the UART session open avoids losing RAM artifacts on serial reopen. The source fixture was 5 seconds of synthetic 440/660 Hz stereo tones; the receiver captured additional transport padding.

Two successful captures each recorded 264 media packets, 2,112 indicated and 2,112 good SBC frames, 0 bad/zero frames, 270,336 stereo PCM frames and a 1,081,388-byte file. In both captures the actual PCM payload was byte-identical. After the initial capture we corrected two independent BTstack WAV header errors: sample count already includes channels and block alignment must be expressed in bytes. Native mono/stereo header and sample regressions passed; the fixed RV32 executable was rebuilt, transferred to RAM with verified SHA-256, and retested.

Corrected capture: 44,100 Hz, stereo signed 16-bit PCM, 270,336 frames, valid RIFF/data sizes and four-byte block alignment. Over a 4.9-second interior signal window, peaks were 440.001 and 659.959 Hz, RMS 8443.08 and 8449.70, respectively, zero clipped samples. Opposite-tone spectral rejection at the measured frequency bins was 112.67/117.15 dB (not a calibrated analog crosstalk measurement).
